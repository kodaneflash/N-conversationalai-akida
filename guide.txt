









## Tavus.io integration overview (concise, detailed)
What it is
- Conversational Video Interface (CVI) from Tavus, embedded with Daily call objects. We create a conversation server-side, then join the Daily room client-side using CVI blocks.

How it’s wired
- Server route `src/app/api/tavus/new/route.ts` calls `createConversation()` in `src/lib/tavus.ts` to POST `https://tavusapi.com/v2/conversations`. It returns `{ conversationUrl, conversationId }`.
- Page `src/app/chat/page.tsx` shows a hero + `Launcher`. Clicking the CTA sets `isOpen=true` for `CviModal` and triggers `createConversation()` via the modal’s `onStart` flow.
- `CviModal` orchestrates 3 steps: landing → HairCheck → session. HairCheck and Conversation are wrapped in `CVIProvider` to share one Daily call object.
- `CVIProvider` (`src/components/cvi/components/cvi-provider`) memo-creates a single `DailyIframe.createCallObject()` and passes it to `<DailyProvider callObject={...}>`.

Supported features
- Conversation creation with optional memories, conversation name, conversational context, audioOnly flag, and callback webhook URL (constructed from request host).
- CVI blocks in use: HairCheck (camera/mic permissions & device selection) and Conversation (1:1 video with Replica). Device controls for mic/camera/screenshare are included.
- Mobile resilience: iOS-safe heights, safe-area padding, singleton Daily object, improved Safari permissions (see `use-start-haircheck.tsx`).
- Meeting status indicator (Waiting/Calling/Connected/Ended).

Not included yet
- No language selector UI; language is sent in the create request by the page.
- No transcripts/CC UI (toggle fields exist in `lib/tavus.ts`, not surfaced).
- No recording controls UI (server supports properties, but disabled in the page).
- No multi-party layout; designed for 1:1 user ↔ Replica.

Files responsible for chatting
- `src/lib/tavus.ts`: builds Tavus API payload; returns `conversationUrl`/`conversationId`.
- `src/app/api/tavus/new/route.ts`: server route to create conversations.
- `src/components/cvi/components/cvi-provider/`: shared Daily call object via React context.
- `src/components/cvi/components/hair-check/`: preflight permissions/devices and Join.
- `src/components/cvi/components/conversation/`: joins via `useCVICall().joinCall({ url })`, renders tracks and controls.
- `src/components/cvi-ui/cvi-modal.tsx`: orchestrates steps and passes `conversationUrl` into `Conversation`.

Styling model
- Tailwind utilities + custom tokens/utilities from `src/app/globals.css` for neon shell and effects: `--dialog-w`, `--radius-container`, `--primary`, `--success`, `.max-w-dialog-w`, `.md:rounded-container`, `.shadow-container`, `.bg-replica`, `.shimmer`.

# FaceTime-style Tavus experience (Launcher + Modal with 3 states) 

How it works (end-to-end)
Launcher renders a compact hero with a background video and a glowing CTA. Clicking the CTA calls its onStart prop (from the page), which opens the modal.
CviModal manages a 3-step flow using local state:
landing: marketing copy + “Start Video Chat” CTA
preflight: HairCheck (camera/mic permissions & device setup) inside a shared Daily context
session: Conversation joins the Daily room via the conversationUrl
CVIProvider exposes a single Daily call object to all CVI blocks, preventing duplicate-call errors and enabling device/permission hooks to function consistently.Key files and responsibilities
Launcher: visual entry and CTA; no data fetching or CVI concerns
CVIProvider: “singleton” Daily call object via React context
CviModal: the complete UX flow and responsive neon shell
